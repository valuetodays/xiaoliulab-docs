# lastUpdated 提交与推送校验

脚本适用于 Node.js 24 及以上版本。它读取 Git 对象和当前文档，比较两个版本的展示数据；不逐次扫描提交历史，不保存数据库或上一版状态文件，也不自动改写时间。

## 本机启用

安装项目依赖后执行：

```powershell
npm run hooks:install
```

安装器把工程内 `.githooks/pre-commit`、`.githooks/pre-push` 复制到本机 Git hook 目录，并设置执行权限。首次克隆或修改 hook 模板后需要重新运行；修改校验脚本本身立即生效。已有自定义 hook 或 `core.hooksPath` 时会停止并提示合并，不会覆盖。

提交前检查实际暂存区；推送前检查每个待更新分支的远程旧版本与本地新版本。失败时 Git 操作终止，输出受影响 URL、维护字段的位置和原因。修正并重新暂存后再提交。Git hook 仍可被显式跳过，本机约束不能代替服务器端分支保护。

## 手动检查与测试

```powershell
# HEAD 与工作区比较，包含未暂存和未跟踪的文档
npm run check:last-updated

# HEAD 与暂存区比较，忽略工作区未暂存的修改
npm run check:last-updated -- --staged

# 两个指定版本比较，适用于推送范围
npm run check:last-updated -- --base origin/dev --head HEAD --range

# 回归测试，包括独立临时 Git 仓库中的 hook 拦截与放行
npm run test:last-updated
```

远程旧版本在本机不存在时，校验报错，需要先执行 `git fetch`。新分支使用空快照作为比较基准。推送只读取指定提交，不把未提交的工作区改动混入结果。

## 校验规则

- 普通文档使用 Git 时间，不允许添加显式 `lastUpdated`。
- 首页、Demo 汇总和思想总览从各自 Frontmatter 读取不加引号的 ISO 8601 日期；思想详情从每个思想定义读取带时区的 ISO 8601 字符串。
- 展示内容变化时，时间必须晚于原值；展示未变化时，提交前检查要求保留原值。
- 拒绝缺失、无效、无时区、未来或倒退的时间。首次添加字段、新页面初始化及修复历史非法值可以使用合法时间，不需要制造额外展示变化。
- 一次推送可能包含“修改后又还原”的多个有效提交，因此范围检查允许展示相同但时间前进；仍拒绝倒退、未来日期和内容已变化却未更新时间。

## 展示数据范围

| 页面 | 比较内容 |
| --- | --- |
| 首页 | 本页正文及 Frontmatter（排除时间）、文章数量和字数。完整字数也出现在统计栏的提示中，因此不只比较缩略文字。构建／部署时间不参与比较。 |
| 思想总览 | 本页正文、思想代码、名称、颜色、说明、各思想文章数量及总览组件的模板／脚本。 |
| 思想详情 | 思想名称和说明、关联文章标题与链接列表、共用 Markdown 模板和详情组件的模板／脚本。各思想独立判断，文章归属变更会检查原归属与新归属。 |
| Demo 汇总 | 本页正文、展示的文档标题、说明、入口及附件链接列表；包含删除或移除最后一个附件的情形。 |

不可见 Markdown 注释、正文软换行整理、组件脚本注释和组件纯样式块变化不要求更新时间。校验复用站点的文章筛选、Demo 链接识别和字数计算函数。

这是针对当前展示结构的确定性检查，不是运行任意历史版本的 Vue 应用。新增展示字段、改变组件依赖或统计规则时，需要同步更新 `scripts/lib/last-updated.mjs` 及测试。脚本静态解析思想定义，不执行旧版本或暂存区里的 TypeScript；思想定义应保持为静态字符串对象数组。

Sitemap 和页面时间是否实际映射正确，仍通过 `npm run docs:build` 检查；本脚本专门检查提交时是否维护了必要的字段。
