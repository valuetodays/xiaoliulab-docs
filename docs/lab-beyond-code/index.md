# 代码之外

这里记录软件开发中技术实现之外的工程问题，关注需求如何交付、团队如何协作，以及长期维护、经验传承和工程判断中的具体经历。

## 内容分类

| 分类 | 内容范围 |
| --- | --- |
| 工程交付 | 需求、排期、优先级、测试衔接、发布与交付 |
| 团队与协作 | 团队角色、专业骨干、跨岗位协作、新人培养 |
| 工程治理 | 长期维护、工程规范、技术债务、机制延续 |
| 经验与成长 | 知识积累、经验传递、技术分享、个人成长 |
| 工程判断 | 风险识别、技术取舍、AI 辅助开发、判断依据 |

## 内容记录原则

- 以真实经历和可确认的事实为基础，说明事件过程、发生条件和逻辑关系。
- 区分已发生的事实与潜在风险，将未经验证的推断标记为假设或待验证内容。
- 不进行人物评价，不讨论谁对谁错，不将个别经历扩大为普遍结论。
- 保留具体情境与适用边界，不将记录写成团队管理教程或个人成功经验总结。
