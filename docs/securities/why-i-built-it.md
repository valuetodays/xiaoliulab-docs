# 为什么我开始自己开发证券软件？

我最初决定开发证券软件，原因其实很简单：

**自己有实际使用需求，而当时使用的证券软件没有提供我想要的功能。**

作为一名程序员，遇到这种情况，我自然会想到：能不能自己写一个？

于是，开始了证券软件的开发。

## 一、现有软件为什么不能满足需求？

证券交易软件已经提供了很多成熟的功能。

例如行情查看、K 线分析、委托下单、成交查询和账户管理。

对于一般的证券交易，这些功能已经能够满足不少需求。

但在实际使用过程中，我逐渐产生了一些更具体的想法。

例如做 T。

我希望在一笔交易实际成交后，程序能够按照预先设定的规则，自动提交反向委托，而不需要自己一直盯着行情、反复操作。

当时使用的软件没有提供符合我需求的这套操作方式。

这并不是说所有商业证券软件都没有类似功能，而是现有工具无法直接满足我的具体要求。

既然如此，能不能通过程序实现？

## 二、从一个具体需求开始

2024 年，我开始尝试将 Java 程序与证券交易接口连接起来。

其中，Java 主要负责交易逻辑，Python 通过 QMT 提供证券交易能力。

最初需要解决的问题并不复杂：

一笔委托提交后，程序怎样知道它是否真正成交？

成交以后，怎样按照预先设定的价差和数量，提交反向委托？

如果没有成交，或者只成交了一部分，又应该如何处理？

这些问题看起来只是几个操作步骤，但真正写成程序时，就需要考虑委托状态、成交回报、数量变化以及异常情况。

这也是我第一次将自己熟悉的软件开发技术，应用到真实证券交易中。

## 三、需求并没有随着自动交易完成而结束

随着实际使用，新的问题开始出现。

交易发生以后，需要保存和整理成交记录。

一笔买入可能对应多笔卖出，也可能有部分数量长期没有完成反向交易。

最初简单的买卖配对方式，逐渐无法满足这些场景。

于是，我开始建立自己的交易记录和中和模型。

后来，使用融资交易，又需要管理融资负债、偿还本金、支付利息以及负债结清等业务。

与此同时，为了研究证券市场，我也逐渐开始保存历史行情、计算技术指标，建设市场数据与分析功能。

这些功能并不是在开发之初就全部规划好的。

**往往是先遇到一个实际问题，再开发相应的功能；使用一段时间以后，又发现新的问题。**

系统就是这样逐步发展起来的。

## 四、为什么继续自己开发？

当然，自己开发软件并不一定比使用成熟产品更省事。

需要编写代码，需要维护数据，还要处理各种意料之外的问题。

有些功能甚至需要反复修改，才能逐渐适应真实业务。

但对我来说，自行开发有一个很直接的好处：

**我能够根据自己的实际需求，决定软件应该怎样工作。**

当发现某个数据模型不合适时，可以修改模型。

当现有分析结果不够用时，可以增加新的统计维度。

当一个功能在实际使用中暴露问题时，可以回头检查代码、数据与设计。

当然，涉及真实资金的交易功能，还必须特别重视验证和风险控制。

自行开发意味着拥有更大的调整空间，也意味着需要自己承担更多维护责任。

## 五、从一个工具到一套系统

回头看，最早的目标只是解决一个具体的自动交易问题。

而现在，相关软件已经涉及交易管理、融资业务、市场数据和分析等多个方向。

它逐渐不再只是一个用于自动操作的小工具。

不过，我并不认为这是一套已经完成的系统。

随着证券业务知识的增加，以及实际使用场景的变化，新的需求还会不断出现。

这也是建立《证券工程》专题的原因。

我希望记录的不只是最终的软件功能，还有这些功能为什么出现、当时如何实现，以及后来为什么需要调整。

**因为自己需要，所以开始开发；因为持续使用，所以不断完善。**

这就是这套证券软件的起点。
