# 关于小刘实验室

小刘实验室是我用来记录个人学习、研究、实验和思考的网站。

这里有软件研发方面的文章，也有证券市场研究、个人实验和生活经历。

这些内容看起来涉及不同领域，但大多有一个共同的起点：**我在实际生活或工作中遇到了某个问题，或者对一件事情产生了兴趣，于是开始研究和尝试。**

有些问题很快就能解决，有些需要花费很长时间。有时实验得到了预期的结果，有时也会发现最初的想法并不成立。

我希望把这些过程记录下来，而不只是留下最后的结论。

## 一、为什么建立小刘实验室

最初，我并没有打算建立一个包含多个专题的网站。

学习软件开发以后，我逐渐养成了自己编写程序、购买服务器和部署应用的习惯。

有时是为了学习一种新的技术，有时是因为工作中遇到过类似问题，想在自己的环境里重新尝试。

后来，我开始把一些实际运行过的程序和实验过程整理成文档。

微信支付是其中一个比较早的例子。

在学习支付接口时，我不太希望读者只是照着文章配置参数、编写代码，最后却不知道整个流程能不能真正运行。

于是，我先实现了可以实际体验的支付功能，再围绕这个结果说明需要哪些接口、系统之间怎样交互，以及开发过程中可能遇到什么问题。

我把这种方式概括为：

**“把结果前置，你先看到效果，再去写代码。”**

后来，随着我开始研究证券市场，又陆续开发了行情数据采集、交易记录管理、技术指标分析和程序化交易等工具。

这些实践产生了新的问题，也产生了新的记录。

网站中的内容就这样逐渐增加了。

## 二、这里记录什么

小刘实验室并不只是一个技术教程网站。

我当然会记录技术知识，但更希望文章能够回答：这个问题从哪里来，为什么要解决它，我实际采用了什么方法，又得到了什么结果。

目前，网站中的内容主要围绕几个方面展开。

### 软件研发

记录工作和个人项目中遇到的软件开发问题，包括系统设计、框架使用、数据处理、自动化和工程实践等。

例如，我曾经因为项目发布需要手工整理大量文件，尝试编写程序自动生成增量发布包。

后来又逐渐接触 Maven、Jenkins 等工具，尝试改进构建和部署流程。

这些经历让我有机会把此前学到的技术应用到具体问题中。

我更愿意从这样的实际问题讲起，而不是单纯罗列某个框架有哪些功能。

### 金融研究与个人实验

证券市场是我在工作之外持续投入时间研究的领域。

最初，我只是对基金交易中很小的价格差感兴趣。

后来，为了判断一种交易方法是否有效，我开始关注历史行情、技术指标、统计样本和交易成本，并尝试开发工具辅助研究。

研究过程中，又逐渐接触到 ETF、分红复投、融资交易、期权和程序化交易等不同问题。

网站中的部分内容是已经完成的实验，部分是正在进行的观察和研究。

我希望保留这些过程中的假设、条件、数据和结果，而不是只记录盈利的交易或成功的实验。

### 个人经历与思考

除了技术和金融，我也会记录自己的成长、求学、工作以及生活中的一些经历。

这些内容不一定能够给别人提供直接可用的方法，但对我来说同样值得保存。

有些事情过了几年以后，记忆会逐渐模糊。当年的想法和后来形成的认识，也未必完全相同。

因此，我希望尽量保留事情原来的样子，同时允许自己在以后补充新的理解。

## 三、七项核心原则

随着记录和实践不断增加，我逐渐整理出[七项核心原则（内核思想）](/core-principles/)。

它们是：

| 核心原则 | 含义 |
|---|---|
| 边界 | 遇到复杂系统，先想清楚谁和谁应该分开，以及各自负责什么。 |
| 留真 | 保留当时真实发生的事实，不用后来形成的解释重写历史。 |
| 复现 | 一次成功不是证据，能够重复验证，结论才更可靠。 |
| 显式 | 重要状态、规则和风险尽量明确表达，不依赖隐含默认和人的记忆。 |
| 克制 | 没有充分理由时不强行动作，不为了使用资源而制造动作。 |
| 演进 | 接受当前结论并非最终答案，在保留历史的基础上持续修正和演进。 |
| 反证 | 方案形成后，不只验证它为什么成立，也主动寻找能够推翻它的反例、极端场景和隐藏假设。 |

这些原则并不局限于某一门技术或某一种业务。

例如，在设计软件系统时，我会考虑不同模块之间的边界，尽量把重要状态和处理规则表达清楚。

在研究交易方法时，我不能因为某次操作盈利就认为策略一定有效，还需要考虑交易费用、统计样本，以及哪些市场情况可能让原来的判断失效。

在记录个人经历时，我则需要区分当年实际发生的事情与现在的理解，避免用后来形成的观点替过去的自己作解释。

这些都是不同问题，但可以使用相同的原则去审视。

七项原则也不是要求每篇文章都必须符合七个方面。

我会根据文章实际涉及的问题，关联其中相关的核心原则。

更重要的是，不能为了让一篇文章符合某项原则，就改变原本的事实或强行补充解释。

## 四、为什么保留过程，而不只是结果

以前遇到技术问题时，我也经常通过搜索引擎寻找解决方案。

有些文章能提供直接可用的代码，却没有说明问题为什么产生、适用于什么条件，或者作者是否真正验证过。

如果照着操作仍然失败，就需要继续寻找其他资料。

这也是我自己写文章时希望注意的地方。

如果条件允许，我希望记录问题出现时的环境、尝试过的方法、遇到的错误，以及最终如何验证结果。

当然，并不是每一次实践都能得到确定的结论。

例如，某个交易策略在一段历史行情中表现不错，并不意味着以后仍然有效；一个技术方案在个人环境里运行成功，也不代表换到其他环境就不会出现问题。

因此，我也希望文章能够说明结论的适用范围，以及尚未解决的问题。

有时，研究过程中发现原来的判断不成立，反而比得到一次符合预期的结果更值得记录。

## 五、文章和想法会继续变化

小刘实验室中的文章不一定一次写完就永远不再修改。

随着实践继续深入，我可能会发现之前遗漏的条件，或者对某个问题有了不同的理解。

这时，我会根据新的事实、数据或实验结果修正文章。

现在使用 AI 辅助写作以后，这种过程变得更加频繁。

我会利用 AI 整理材料、提出质疑、检查事实和讨论不同方案，但最终仍然需要回到实际经历、代码、数据和能够核实的资料。

AI 提出的修改建议也不一定正确。

如果建议与事实不符，或者为了让文章更完整而加入当时并不存在的想法，就不应该采纳。

我希望网站能够不断完善，但也尽量保留它是怎样一步步发展到今天的。

## 六、希望小刘实验室能够做什么

现在，小刘实验室首先还是我自己的学习、研究和实验记录。

我并不要求每篇文章都能立即帮助别人，也没有给网站设定必须达到多少访问量的目标。

但既然把这些内容公开，我也希望它们有机会对其他人产生一点实际帮助。

例如，有人正在研究相似的软件问题，可以参考我已经尝试过的方法，少走一些弯路。

或者有人对某个实验的结论有疑问，能够指出其中遗漏的条件，提供不同的分析角度。

我尤其希望以后有人能够带着真实的软件研发问题来交流：

“我在软件研发中遇到了这个问题，看了网上教程还是不明白，你能不能帮我研究一下？”

如果一个问题值得研究，我也愿意尝试分析、验证，再把过程记录下来。

至于网站以后会增加哪些内容，我暂时没有一份固定的规划。

我还会继续工作、学习和开展个人实验。研究的问题可能会变化，使用的技术也可能会变化。

小刘实验室会随着这些实践继续更新。

我希望它能够长期保留那些真实发生过的事情，以及我为理解和解决问题所做过的尝试。
