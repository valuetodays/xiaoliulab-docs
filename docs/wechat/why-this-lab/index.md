# 为什么会有这个实验室？

如果你曾经第一次接触微信支付，大概率经历过这样的过程：

* 搜索了很多教程，每一篇都介绍得很详细，但不知道应该先看哪一篇。
* 好不容易配置完成，却不知道自己的配置到底有没有问题。
* 网上代码很多，却无法确认是否经过真实验证。
* 支付成功了，却收不到回调；或者回调收到了，却不知道下一步应该做什么。

很多开发者并不是不会写代码，而是在第一次接入微信支付时，需要花费大量时间去拼凑零散的信息。

这正是建立**微信支付实验室**的原因。

## 我希望解决什么问题？

微信支付实验室并不是一本介绍微信支付所有功能的百科全书。

它更像是一份真实的实验记录，希望帮助第一次接触微信支付的开发者，以尽可能短的时间完成第一次真实支付。

我希望你能够：

1. 尽快看到支付效果，而不是先学习大量概念。
2. 使用真实验证过的代码，而不是无法确认是否可运行的示例。
3. 在完成第一次支付之后，再逐步理解整个支付流程和背后的设计思想。

对于第一次接入微信支付来说，**先成功，再理解**，通常比**先理解，再尝试**更容易建立信心。

## 为什么选择"实验室"而不是"教程"？

网上已经有很多优秀的微信支付教程。

微信支付实验室并不希望重复介绍官方文档已经说明的内容，而是希望回答那些开发过程中真正会遇到的问题。

例如：

* 为什么生成不了支付二维码？
* 为什么支付成功却收不到回调？
* 为什么查询订单和支付回调都需要保留？
* 为什么不同支付方式的接入流程看起来相似，却又有所区别？

每一篇文章，都希望围绕一个真实问题展开，而不是为了介绍某个知识点而介绍知识点。

## 真实验证，比代码更重要

微信支付实验室坚持一个原则：

> **没有经过真实验证的流程，不作为最终结论。**

所有示例都以真实商户、真实支付流程和真实接口验证为基础。

如果某项能力由于主体限制、权限限制或其他客观原因暂时无法完成完整验证，我会明确说明原因，而不是提供未经验证的示例代码。

## 希望节省屏幕前的你的时间

建立这个实验室，最初只有一个很简单的想法：

**希望帮助第一次接触微信支付的开发者，少走一些弯路，节省一些时间。**

如果你能够因为这里的一篇文章，更快完成第一次支付、更快定位一个问题，或者少踩一个已经踩过的坑，那么这个实验室就已经实现了它存在的价值。

## 后续内容

微信支付实验室将持续围绕真实开发过程中遇到的问题进行整理和更新，包括但不限于：

* Native Pay
* JSAPI Pay
* Code Pay
* H5 Pay（完成真实验证后）
* 支付回调
* 订单查询
* 退款
* 常见问题与排查
* 真实实验记录

希望这些内容，能够陪伴你完成从第一次接入，到真正理解微信支付整体流程的全过程。
